# Changelog

All notable changes to ProxyX are recorded in this file.

The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html). The project is pre-1.0; minor versions may contain breaking changes to configuration keys, APIs and schemas, and each such change is listed here.

## [Unreleased]

### Added

- **[Backends guide](docs/backends.md)**: a support matrix of every backend family ProxyX uses (relational, object store, Redis and Valkey, ClickHouse, OpenSearch and Elasticsearch, Kafka and RabbitMQ), the reason for each, and how to share one set of instances with other products.
- `database_schema` (`PROXYX_POOL_DATABASE_SCHEMA`, `PROXYX_CONTROL_DATABASE_SCHEMA`): a PostgreSQL schema per plane, so several products or both ProxyX planes share one database with separate tables and migration history. `migrate` creates the schema. Refused for MariaDB and SQLite.
- Object store profiles for traffic view exports: `traffic_views_s3_profile` (`standard`, `edge`, `self-hosted`, `compatible`), `traffic_views_s3_path_style`, `traffic_views_s3_credentials_file` and `traffic_views_prefix`, with combinations that cannot work refused at load time.
- `[capture_store.opensearch].kind`: ProxyX detects OpenSearch or Elasticsearch and the version from `GET /` at migration and ingester start, refuses an unsupported version, and with `kind` set refuses the other engine.
- `proxyx migrate control --target clickhouse` creates `clickhouse.database` when it is set, so each product on a shared ClickHouse gets its own database.
- Integration tests against real services in throwaway containers (`ci/backends-up.sh`, the `backends` CI job): an S3-API store with ClickHouse, Redis and Valkey (prefix and ACL isolation), ClickHouse namespaces, OpenSearch and Elasticsearch, Kafka, RabbitMQ and shared PostgreSQL schemas.
- **Passive capture analysis** in the MCP server (`[analysis]`, off by default; see [ai.md](docs/ai.md#passive-capture-analysis)): a scope-aware, evidence-bearing boundary shared by all analysis tools.
  - `open_analysis_scope`, `analysis_capabilities`, `get_analysis_result`, `delete_analysis_result`: server-held scope handles inside operator-listed sources and origins, intersected into every query branch and checked against every returned capture; keyed per-engagement fingerprints instead of credential values; evidence references with coverage, truncation and lag; bounded retention.
  - `analyze_auth_flows`: authentication mechanisms, cookie attributes, and issue, send, replace, clear and reuse edges; JWT structure is decoded without verification.
  - `scan_sensitive_data`: credential, personal-data and high-entropy candidate findings with masked previews, locations and fingerprints, never values; explicit coverage loss; operator-owned custom rules.
  - `draft_traffic_query`, `run_traffic_query`: natural-language questions compiled to the query language by templates (optionally a model), with the scope intersected into every OR branch, an explicit cost, unsupported clauses (a time range is never simulated) and a separate run step.
  - `infer_api_schema`, `get_api_schema_draft` and the `proxyx://analysis/{org}/{draft_id}/openapi` resource: OpenAPI 3.1 drafts of what was observed (`x-proxyx-observed-required`, evidence, diagnostics, no examples).
  - `open_capture_feed`, `read_capture_feed`, `close_capture_feed` and the `proxyx://feeds/{org}/{feed_id}` resource: cursor-based polling of stored captures with stable ids and an explicit statement that it is not a live stream.
  - Model calls from analysis tools need `analysis.allow_external_llm`, cite only evidence the analysis produced, and are audited (`model` and `evidence` audit phases) without prompts or content.
- `classify_block_page` returns a `subtype`, evidence references, `confidence_kind`, `abstained` and the rules' `detector_version`; it tells authorization answers, maintenance pages and proxy-made refusals from blocks, abstains on pages that only discuss a CAPTCHA, accepts `capture_ids` and reports whether repeated observations make a classification eligible for reporting. Rules are measured on published fixtures.
- `llm.alias` names the model endpoint in audit records.

### Changed

- Traffic view export keys now start with `traffic_views_prefix` (`proxyx/` by default): new exports are `proxyx/traffic-views/<org>/<view>.parquet`. Exports finished before the upgrade keep the key stored on their row; an export still running during the upgrade is written again under the new key.
- The benchmark harness no longer runs `FLUSHDB`: it refuses a Redis database that is not empty.
- **`classify_block_page` no longer reports.** The `report` and `dry_run` arguments are removed: classification is a pure read that returns the arguments of a separate `report_block_signal` call. With `[analysis]` enabled, `report_block_signal` waits for an operator's approval unless `analysis.blocks.report_requires_approval = false`.
- A model call has one absolute deadline: the `json_object` fallback attempt shares `llm.timeout_secs` with the first attempt, and all prompt fragments share one budget (`llm.max_input_chars`).

### Fixed

- **Shared PostgreSQL instance.** Two migrations no longer reach outside ProxyX's own schema. `20260703000001_drop_partman` dropped the `pg_partman` and `pg_cron` extensions with `CASCADE`, the `partman` schema and the `partman-maintenance` cron job of the whole database, which destroyed the extensions and jobs of every other product on it; it now removes only the `partman` configuration row of its own schema's `http_captures` table, when that table exists and the role may change it. `20250425000002_create_http_captures` created `pg_trgm` and two trigram indexes that failed with `operator class "gin_trgm_ops" does not exist` when the extension lived outside `public`; the unused indexes and the extension are gone from it (the table is dropped by a later migration), and `migrators!` no longer installs extensions. Both files changed after release 0.1.0, so `migrate` now records the new checksum for a database that holds exactly the checksum of the released text (pinned in `crates/control/src/db/mod.rs`) before sqlx verifies the history; any other checksum is still refused with `VersionMismatch`. Once repaired, `migrate` of release 0.1.0 refuses that database (its checksums no longer match its own files): upgrade every process, do not roll back. Nothing else changes in a database that already applied them; an extension or cron job an old ProxyX installed stays and can be removed by hand.
- Traffic view export failed on ClickHouse 25.8 with `Code: 50 ... Internal type 'UUID' of column 'id' is not supported for conversion into Parquet data format`. The export now writes `id` as text (`toString(id)`), and filters in a subquery so the alias cannot shadow the column. **The `id` column of new Parquet exports is a string**, where it was a 16-byte UUID on servers that could write one.
- Redis, ClickHouse and OpenSearch URLs with a password (`redis://user:secret@host/0`, the documented ACL form) were logged in full at start by the control API, the ingester and the session proxy, and Sentinel URL errors echoed them. The password (and a user info without a colon, and `password`, `token`, `key`-like query parameters) is now masked everywhere a URL is logged.
- Credentials in the environment for a backend a deployment does not select (`PROXYX_CONTROL_CLICKHOUSE__USER` with the OpenSearch store, `PROXYX_CONTROL_RABBITMQ__USERNAME` with Redis streams, and the Kafka SASL and OpenSearch credentials, in the control plane and the session proxy) failed the configuration load with `missing field url`. A table that holds only credential keys (and the `local_single_node` switch of `[clickhouse]`) now counts as absent; any other incomplete table is still an error.
- The default capture stream ignored `redis_key_prefix`: two deployments with different prefixes on one Redis or Valkey shared `proxyx:request_log`, and an ACL user fenced to `<prefix>:*` was refused. Unset, `request_log_stream` (control plane) and `request_log.stream_name` (session proxy) are now `<redis_key_prefix>:request_log`. **Deployments with the default prefix are unchanged. A deployment with another `redis_key_prefix` and no explicit stream name moves to a new stream on upgrade:** set both names to `proxyx:request_log` to keep the old one, or stop the session proxies, let the ingester drain it and start both sides on the new name ([capture-pipeline.md](docs/capture-pipeline.md#broker)).
- A requested `max_body_bytes could exceed `limits.max_body_bytes`; it is now the smaller of the two.
- Resource reads bypassed `limits.max_result_bytes`; tools and resources share one ceiling.
- Capture output removed fewer secrets than the model-bound path (JSON body members, form fields, URL query and header values); both now use one cleaner, applied before bodies are clipped.
- The untrusted-data wrapper could be closed by a differently cased or spaced closing tag in captured content.
- An oversized tool call could leave an audit line longer than the window the log's tail reader scans, after which every later audit write failed; arguments over 256 KiB are now recorded by size and digest.
- Redaction missed camelCase member names (`accessToken`) and JWT-shaped values outside a recognized header or member; both are now removed from tool output, resources and model input.

### Security

- **Session proxy verifies upstream TLS.** Intercepted connections check the upstream certificate chain and host name against the system roots plus an optional `[tls] ca_bundle`. A failure answers `502` with `X-ProxyX-Error: upstream_tls` and captures nothing. Exceptions are explicit: `[tls] verify_upstream = false`, `[tls] insecure_upstream_hosts`, or `insecure_upstream_tls: true` on one session (client: `CreateSessionRequest::insecure_upstream_tls`), for authorized testing only.
- Non-intercepted HTTP forwarding in the session proxy serves one exchange per upstream connection and then closes it, so each pipelined or keep-alive request is authenticated, routed and stripped of `Proxy-Authorization` on its own.
- Chunked bodies in the session proxy bound chunk-size lines, chunk extensions and trailers (each and in total) with checked arithmetic and read deadlines, on the HTTP/1.1 and HTTP/1.1-to-HTTP/2 paths.
- Compressed WebSocket messages are bounded before they are buffered (`[tuning] max_ws_compressed_message_bytes`, default 16 MiB); a larger message closes the WebSocket with `1009`.
- CA directories are created `0700` and key files `0600` exclusively; the session proxy and control plane refuse a CA key file that is group- or world-readable or owned by another user.
- Control API rate limits key on the canonical credential (a hash of the normalized bearer token, or org and principal for trusted headers) and add an independent per-source-address bucket checked before authentication, both from `[http] per_key_rps` / `per_key_burst`.
- Edge ACLs evaluate every resolved address on its own; TCP, UDP ASSOCIATE and BIND connect only to addresses that the rules allow, in resolver order, so a name resolving to a mix of allowed and denied addresses can no longer reach the denied ones.
- Edge requests through a parent send the approved numeric address (CONNECT target, SOCKS5 IPv4/IPv6 address, absolute-form URL) while keeping the logical `Host` and TLS SNI, so the parent cannot re-resolve the name to a different address. This includes the final hop of a chain.
- Edge HTTP requests whose `Connection` header nominates framing or routing headers (`Content-Length`, `Transfer-Encoding`, `Host`, `TE`, `Trailer`, `Proxy-*`, or `Upgrade` without an upgrade) are refused with `400` before authentication, closing a request-smuggling path.
- Edge SOCKS5 UDP ASSOCIATE holds the per-user and per-source connection slots for as long as the control connection lives, like TCP and BIND.
- MCP session tools return opaque per-server session handles instead of session ids, which are proxy credentials. Pending `extend`/`end` changes keep the real id in the private `0600` change file, so approvals survive a restart. Basic auth and proxy URL userinfo carrying a session id are redacted.
- MCP servers scoped with `allowed_orgs` filter every read tool and resource to those orgs before pagination, check session ownership first, and no longer expose the shared audit history.
- Nested MCP mutations (`classify_block_page` with `report`, stored configuration changes) enforce the tool allow and deny lists of the action they perform, at proposal and at apply time.
- Approved MCP changes expire at their deadline, consumption re-checks expiry and revocation atomically, and `proxyx mcp reject` also revokes approved, not yet applied changes.
- MCP LLM tools build prompts from cleaned captures: authorization, cookie, proxy and API-key headers, credential query parameters and body secrets are removed before any request leaves the process.
- The limiter service closes connections that do not finish the handshake within 5 s or stay idle longer than `PROXYX_LIMITER_IDLE_TIMEOUT_MS` (default 60 s), so idle peers cannot hold its connection slots.
- CloudFront URL signing uses `rsa` 0.10, which removes the timing side channel of RUSTSEC-2023-0071; the advisory is no longer ignored in `deny.toml`.
- Container base images (`docker/Dockerfile`, `docker/Dockerfile.egress`) are pinned by manifest-list digest, and Dependabot proposes updates for Docker and Compose images. The security workflow adds dependency review on pull requests and the OpenSSF Scorecard on `main`; CodeQL also analyzes the Python prober, scoped by `.github/codeql/codeql-config.yml`. CI installs native build dependencies through `ci/install-build-deps.sh`, which retries against the primary Ubuntu archive when the runner's package mirror is unreachable.

### Changed

- **Third-party products, services and vendors are no longer named.** Integrations work under neutral names; the exact strings an external service needs (default gateway hosts, echo and reputation origins, reply fields, a library's own commands) stay in the code and data files on lines marked `wire-compat`, and strings matched on target sites on lines marked `detection-data`. `ci/lint-provenance.py` enforces it (`third-party-name`, plus `host-path` and `privileged-pr-trigger`). Nothing was released under the former names, so there are no aliases. The new names:
  - Shipped adapters (`data/adapters/`) are named for product type and credential grammar: `res_user_suffix` (residential, options appended to the username), `res_pass_suffix` (options in the password), `res_zone` (full zone username), `res_numeric_sticky_http`, `res_numeric_sticky_socks5`, `res_numeric_rotating_http`, `res_numeric_rotating_socks5` (numeric session id, file `res_numeric_session.toml`) and `isp_static_port` (static ISP, one port per IP). The adapter ids, files and the secret files they name (`<id>_user`, `<id>_pass`) all change, as do provider ids in inventory files, policies (`match`, `providers`), org blocks and `px-prov-<id>` usernames that name them.
  - Reputation scorers are named for what they measure: `fraud_score`, `abuse_confidence` and `proxy_risk`. This changes the key files (`fraud_score_api_key`, `abuse_confidence_api_key`, `proxy_risk_api_key`), the settings (`fraud_score_base_url`, `abuse_confidence_base_url`, `proxy_risk_base_url`, `proxy_risk_customer`), their environment variables (`PROXYX_POOL_FRAUD_SCORE_BASE_URL`, `PROXYX_POOL_ABUSE_CONFIDENCE_BASE_URL`, `PROXYX_POOL_PROXY_RISK_BASE_URL`, `PROXYX_POOL_PROXY_RISK_CUSTOMER`), the `check` label values of `proxyx_pool_check_failures_total` and the stored `source` of reputation scores.
  - Exit-IP check kinds (`exit_ip_services`, the `check` metric label) are named for the response format they read: `ip_json`, `trace_lines`, `ip_country_json` and `ip_country_iso_json`.
  - Prober block reasons are named for the kind of page: `js_challenge`, `captcha_frame`, `captcha_widget` and `sorry_redirect`. The prober module is `proxyx_prober.browser_driver` (it drives a headless browser through the automation library named in `pyproject.toml`).
  - The LLM endpoint of `[llm]` is documented as a chat-completions compatible API; MCP client setup is documented generically.

- Upgrade the OpenTelemetry family to 0.33 with tracing-opentelemetry 0.34, SQLx to 0.9, HMAC/SHA digests to the digest 0.11 family, and jemallocator to 0.7, preserving trace propagation, database backend support, and signing output.

- Upgrade Sentry and sentry-tracing to 0.49, the ClickHouse client to 0.15, x509-parser to 0.18, base64 to 0.23 and brotli to 9, and the Rust toolchain and builder image to 1.99.0 (`rust-toolchain.toml` and the Dockerfile pin the same version). The Sentry tracing integration installs the span, breadcrumb and error layers instead of the deprecated combined layer, with unchanged behavior: ERROR records are error events, WARN and INFO records are breadcrumbs, `sample_rate` and `traces_sample_rate` apply as before, and traces stay off at `0.0`. ClickHouse queries set per-query settings with `with_setting`. The development Compose stack runs MariaDB 13, Valkey 9, ClickHouse 26.10, OpenSearch 3 and Kafka 4.3.1.

- Edge request and response header limits now reject complete oversized heads regardless of buffered read segmentation, while retaining exact-limit heads and pipelined bodies. HTTP parent reuse includes every affinity attribute and configuration generation, preventing stale source-address reuse across clients or reloads.

- The Kafka consumer's security protocol follows the configured sections, like the producer: `ssl` with `[kafka.tls]`, `sasl_plaintext` with `[kafka.sasl]` alone, `sasl_ssl` with both. Earlier builds used `sasl_ssl` whenever SASL was set, which a producer without TLS could never talk to.
- `proxyx migrate control --target clickhouse` no longer creates the broker topic; `--target all` (the default) and the new `--target broker` do.
- A malformed capture envelope is rejected instead of acked: with RabbitMQ it lands in the dead-letter queue, with Redis Streams and Kafka it is acked and skipped as before.

### Deprecated

- `broker_kind = "redpanda"`, the `[redpanda]` section and the `PROXYX_*_REDPANDA__*` variables are aliases of `kafka`, `[kafka]` and `PROXYX_*_KAFKA__*`. They keep working for one more release and log a warning at start; setting `[kafka]` and `[redpanda]` together is an error.

### Known limitations

- Pre-1.0: configuration keys, APIs and schemas can change between minor versions.
- Captures are delivered at least once. ClickHouse collapses a replayed capture only at merge time and only when the sort key tuple matches; a publish retried after an ambiguous failure gets a new `session_offset` and is never collapsed, and the materialized views keep every replay. Reads through the query layer de-duplicate by `id`; exports and the time-series and summary queries do not. See [capture pipeline](docs/capture-pipeline.md#duplicates-and-deduplication). The OpenSearch capture store does not have this caveat: it stores a capture once.
- The session proxy drops a capture after five failed publish attempts (about a second of backoff in total), so a broker outage longer than that loses captures; `captures_dropped_total` counts them.
- `GET /rpc/processed` reports `all_processed` as soon as any session of the source is closed. `ratelimit_wait_ms` is recorded as 0.
- The shipped ClickHouse DDL assumes a replicated cluster with a `tiered` storage policy; a single node needs `PROXYX_CONTROL_CLICKHOUSE__LOCAL_SINGLE_NODE` set for `proxyx migrate control`.
- TCP keepalive cannot be set on Redis sockets with the pinned client library; Redis calls are bounded by timeouts instead.
- No binaries, container images or crates.io packages are published; build from source.
